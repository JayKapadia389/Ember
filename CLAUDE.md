# Ember

Distributed job scheduler for running inference jobs on peer-hosted GPUs.

- `coordinator/` Spring Boot app: registers workers, accepts jobs, schedules them.
- `worker/` Python agent: runs on a GPU machine, polls for jobs, runs inference.
- `docs/decisions.md` decision log. Read it before changing design.

## Repo state: mid-migration from a prototype

The repo contains two generations of code:

- **Prototype:** the first throwaway version, built to prove the coordinator and
  worker could talk. Recognizable by not following the conventions below
  (layered packages, raw `vram` instead of `vramMb`, a `GET /jobs/next` endpoint,
  a single-file Python poll loop).
- **New:** domain-packaged code following the conventions below.

Rules for working in this state:

- Don't extend prototype code. New work goes into the domain packages.
- Don't delete prototype code without asking. Point it out and propose the removal.
- When prototype and new code overlap (two job entities, two registration paths),
  the new code is the one to keep. Flag the duplicate.

Status of the new code:

| Area | Status |
|---|---|
| `worker/` domain | Done for v1: register only, `getSpecs` service method |
| `job/` domain | Written: create, status, result submission, artifact download, `claimNext` |
| `scheduling/` domain | Not built. Poll endpoint that calls `WorkerService.getSpecs` and `JobService.claimNext` |
| Python worker | Prototype poll loop. Needs updating to the new poll endpoint and multipart result upload |

## Conventions (coordinator)

- Package by domain: `job/`, `worker/`, `scheduling/`. Layers live inside each domain.
- Domains call each other through public service methods. Never through another
  domain's repository, never over HTTP.
- Repositories are package-private.
- No JPA relationships across domains. Store the other domain's ID as a UUID.
- Entities don't leave their domain. Return a record (e.g. `WorkerSpecs`, `ClaimedJob`).
- No `@Data` on entities. Use `@Getter @Setter @NoArgsConstructor`.
- `@Transactional` from `org.springframework.transaction.annotation`, never `jakarta`.
- Checked exceptions don't roll back transactions. Wrap I/O errors in unchecked ones.

## Database

- Postgres 18. Schema managed by Flyway in `src/main/resources/db/migration/`.
- `ddl-auto: validate`. Hibernate never changes the schema.
- Never edit an applied migration. Add a new versioned one.
- TIMESTAMPTZ for time columns. VARCHAR for enum columns, not Postgres ENUM types.
- Job claiming is one statement: `UPDATE ... WHERE id = (SELECT ... FOR UPDATE SKIP LOCKED) RETURNING *`.
  Never select then update in separate steps.
- Worker state (live, busy) is derived from `last_seen_at` and jobs, not stored.

## v1 rules

- Job statuses: QUEUED, ASSIGNED, COMPLETED, FAILED.
- No cancel, no payments, no authentication, no deletes of workers.
- Worker ID is generated by the coordinator; the worker saves it to a local file and
  sends it as the `X-Worker-Id` header.
- VRAM is in MB everywhere.
- Fixed model catalog (`ModelCatalog` enum): `gpt2`, `stable-diffusion-1.5`.
- Workers poll; the coordinator never connects to a worker.
- No message brokers (RabbitMQ, Kafka). Postgres is the queue.

## Ask before

- Making a design choice that isn't covered in `docs/decisions.md`. Present the
  options and tradeoffs instead of picking silently. The owner decides designs.
- Adding infrastructure or new dependencies.
- Changing the schema.
- Deleting code.

When a decision gets made, add an entry to `docs/decisions.md`.
